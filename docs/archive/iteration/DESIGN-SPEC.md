# GoalCal Web 实现设计规范

## 1. 范围与依据

- 本规范只覆盖新应用 `/app/`：今天、目标、日历、新目标、设置和全局 GoalCal 助手。旧 Streamlit 继续位于 `/`，不改样式、不跳转替换；本轮不做生产部署。
- 唯一视觉来源为 `design-preview/today-balanced.html`、`design-preview/pages.html`，行为同时受 `docs/archive/iteration/CONTRACT.md` 约束。冲突时以契约为准。
- 保留暖月白、低对比边框、自然宽度单列今天页、目标主从布局、日历周视图加待安排区、助手右侧抽屉的既定体验，不引入新视觉风格。
- 原型中的对比切换栏、静态示例数据、演示链接均不进入产品。助手不显示“当前上下文”等上下文标签、切换器或管理入口；通过消息内容、页面目标参数和自然语言消歧完成隐式引用。
- 时间候选不使用原型中的单选按钮和“安排所选时间”二次确认。点击或键盘激活某个候选即执行该候选，成功后提供撤销；有候选时输入框仍可编辑、发送。

## 2. 设计令牌

### 2.1 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `bg` | `#FAFAF8` | 页面底色、目标描述输入区 |
| `surface` | `#FFFEFD` | 卡片、输入控件、助手面板 |
| `surface-soft` | `#F4F4F1` | 次级区域、选中目标、用户消息、进度轨道 |
| `sidebar` | `rgba(244,244,241,.86)` | 桌面侧栏，配背景模糊 |
| `ink` | `#1D1D1F` | 主文字、主按钮 |
| `muted` | `#6E6E73` | 次级文字、元信息 |
| `faint` | `#A1A1A6` | 占位文字、时间轴；不得用于关键操作 |
| `line` | `rgba(29,29,31,.08)` | 分隔线、卡片和输入框边框 |
| `accent` | `#303638` | 主按钮、品牌、今日标记、完成态 |
| `accent-soft` | `#ECEEEF` | 头像、选中期限与时段 |
| `blue` | `#6B7F89` | 助手图标、目标时间块、进度、链接 |
| `blue-soft` | `#EDF0F1` | 目标日程底色 |
| `nav-active` | `#EAEAE6` | 当前导航项 |
| `current-bg` | `#F6F6F3` | 今天时间线当前项 |
| `selected-bg` | `#F6F7F6` | 助手或列表选中背景；候选本身不再保留单选态 |
| `external-event` | `#EEF0F1` / `#939B9F` | 固定日程底色 / 左边线 |
| `toast` | `rgba(28,29,29,.92)` | 成功与撤销提示底 |

状态不能只靠颜色表达；错误、完成、过期、冲突均须有文字或图标。错误和空态仍使用上述中性色体系，不新增大面积警示底色。

### 2.2 字体与排版

- 字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang SC", "Helvetica Neue", Arial, sans-serif`；正文抗锯齿，默认字距 `-0.01em`。
- 数字时间、日期轴和时长使用等宽数字（tabular numerals）。日期时间按 `User.timezone` 显示，不暴露 UTC、版本号、操作 ID 或内部 ID。
- 页面 H1：30px / 1.2 / 700，字距 `-0.045em`；新目标 H1 为 32px；移动端统一 26px / 1.2。
- 今天焦点标题：24px / 1.3 / 680，字距 `-0.035em`；助手内焦点标题 22px；目标详情 H2 为 22px；下一步标题 16px。
- 区块标题 13px / 680；区块标签 11px / 650，字距 `.06em–.07em`；正文和控件主要 12–14px；元信息 10–12px。
- 日历轴可用 9px、日历事件标题 10px、正文 9px，但必须支持浏览器文字放大，且详情中提供完整可读信息。
- 品牌 20px / 720，导航 14px / 520。正文行高至少 1.5，说明文字 1.6。

### 2.3 圆角、阴影、图标与间距

- 卡片圆角 13px；普通控件 9px；目标行 10px；下一步容器 11px；日程块 6px； chip 999px。
- 卡片阴影：`0 1px 2px rgba(20,22,24,.02), 0 8px 24px rgba(20,22,24,.025)`。日历、设置卡、助手内迷你时间线不用阴影。
- 标准图标 18×18px，线宽 1.7，圆角线帽与连接；品牌标记 27×27px、圆角 9px；头像 32×32px。
- 以 4px 为间距基准；常用间距 8、12、16、20、24、32px。分隔优先使用 `line`，不靠额外阴影堆叠层级。
- 进度条高 5px、轨道 `surface-soft`、填充 `blue`、全圆角；同时显示百分比或完成步数。

## 3. 应用框架与响应式

### 3.1 桌面与紧凑桌面

- 默认应用网格为 `218px + minmax(0,1fr)`，侧栏至少撑满视口高度。侧栏内边距 30px 18px 22px，右侧 1px 分隔，背景模糊 24px、饱和度 120%。
- 品牌左右内边距 12px；导航距品牌 42px，项间距 7px；导航项高 43px、左右内边距 13px，图标与文字间距 12px。
- 侧栏不放常驻“新目标”按钮；入口统一放在目标页。用户资料固定在侧栏底部，上边框分隔、顶部内边距 19px。
- 今天页主区内边距 36px 42px 40px；内容最大宽 1040px、水平居中。其他页主区内边距 34px 38px。
- 视口宽 `≤900px` 且仍为非移动布局时，侧栏降为 180px；今天页主区内边距改为 28px 24px，其他页使用 24px。
- 宽桌面打开助手时，可按原型变为 `218px + minmax(560px,1fr) + 400px` 三栏。可用空间不足时，助手改为覆盖式右侧抽屉，不能挤压出横向页面滚动或遮挡当前操作；关闭后恢复原页面宽度和滚动位置。

### 3.2 移动端

- `≤720px` 使用单栏，主区内边距 20px 16px，底部为内容预留导航与安全区空间。侧栏转为固定底部导航，包含今天、目标、日历、设置；当前项同时使用 `nav-active` 和文字/图标状态。新目标入口保留在目标页顶部。
- 底部导航每项最小触控区 44×44px，高度 60px 加设备安全区；不遮挡 Toast、输入框或最后一行内容。
- 顶栏允许换行，标题与主操作不可重叠；次要操作可换到下一行，但不使用只有图标的含糊按钮。
- 卡片内边距降为 16px；按钮和输入控件在移动端最小高 44px，文本输入字号至少 16px。操作组可换行，主操作优先，不横向溢出。
- 目标、设置和日历按后文改为单列；不得把桌面周视图或主从布局整体缩小。320px 宽和 200% 缩放下仍无页面级横向滚动。

## 4. 页面与组件规格

### 4.1 今天

- 顶栏为日期 eyebrow、H1 和“问 GoalCal”按钮。助手按钮桌面高 39px、左右内边距 14px，图标使用 `blue`。
- 焦点卡距顶栏 29px，桌面内边距 23px 25px。目标名距区块标签 14px，步骤标题上下间距 9px；右侧时间胶囊为 7px 10px 内边距、8px 圆角。
- 操作区距元信息 21px，按钮间距 9px；桌面按钮高 37px、左右内边距 15px，主按钮最小宽 82px。进行中时显示“进行中”和实际开始信息；主操作转为签到，不重复提供开始。
- 待恢复事项条最小高 45px，左右内边距 4px，项目间距 22px。没有待恢复事项时整条移除，不保留空白。
- “今日安排”标题区上间距 24px、下间距 10px。时间线卡片每行最小高 66px，网格为 `66px + minmax(0,1fr) + auto`，左右内边距 21px、列间距 14px。
- 目标事件用蓝点和文字归属，固定日程用灰点；当前项加 `current-bg`。完成、跳过、部分完成须显示状态文字，不只降低透明度。
- 移动端焦点标题和时间可分两行；时间线行网格改为 `52px + minmax(0,1fr)`，时长放在内容第二行，左右内边距 14px，最小行高 64px。

### 4.2 目标

- 页面副标题 13px， margin 为 11px 0 25px。主从容器最大宽 1120px，列宽 `290px + minmax(480px,1fr)`，间距 24px。
- 目标列表卡片内边距 9px；列表标签内边距 9px 10px 11px。目标行内边距 15px 14px、下间距 4px，选中行使用柔和底和 1px 边框；标题 13px / 1.45 / 650，元信息 10px。
- 详情卡内边距 24px。详情头部间距 18px；进度区为 `1fr + auto`，间距 12px，上下 margin 20px / 24px。
- “下一步”容器内边距 17px、圆角 11px；操作区上间距 15px。阶段区上间距 26px；阶段行最小高 42px，网格 `23px + 1fr + auto`，间距 10px。
- 步骤区上间距 24px；步骤行内边距 13px 0，网格 `20px + 1fr + auto`，间距 10px。完成步骤有勾选和删除线，当前阶段用环形标记并附文字。
- 可用主区不足 794px 时改为单列：先目标列表，后详情。移动端选择目标后进入详情视图并提供“返回目标列表”，浏览器返回同样有效；不能在窄屏同时压缩两栏。
- 无目标时只显示空态和“新目标”，不渲染空详情。目标不存在或已归档时显示说明和返回入口，不展示缓存冒充最新数据。

### 4.3 日历

- 页面最大宽 1180px。桌面网格为 `minmax(650px,1fr) + 226px`，间距 20px；右侧为“尚未安排”待安排区。
- 周表头和表体均为 `50px + repeat(7,1fr)`；表头高 57px，表体高 624px。时间刻度每 48px 一小时，今日日期圆标 25×25px。
- 日程块左右各留 5px，圆角 6px、内边距 7px 6px、左边线 2px。高度按时间比例计算，极短日程需保证可操作的最小高度，视觉超出部分不覆盖相邻事件；完整标题、目标名和时间在详情中可读。
- 固定日程为灰底灰边，目标块为蓝底蓝边，缓冲块标为“缓冲”。完成事件可降至 `.58` 透明度并加“已完成”；取消/跳过事件加状态文字，不仅依赖颜色。
- 图例距日历 12px，项目间距 15px。拖动只是快捷方式；每个事件和待安排项必须有点击打开的详情及键盘可用的“调整时间”流程。冲突时保留原位置并说明原因。
- 待安排卡内边距 16px；条目内边距 12px、圆角 9px、上间距 9px，显示步骤标题、明确目标名、预计时长和“找时间”。
- 移动端默认单日视图：表头与表体改为 `50px + 1fr`，仍使用 48px/小时和 624px 表体；提供上一天、下一天、今天和日期选择。待安排区移到日历下方，图例可换行。周视图不得压缩成七条窄列。
- 新建日程、移动和取消均使用真实请求；取消后提示可恢复/撤销。没有事件时仍保留网格，并显示“这一天还没有安排”；待安排为空显示明确空态，不放入示例任务。

### 4.4 新目标与计划草稿

- 内容最大宽 720px，水平居中，桌面顶部内边距 22px。表单卡片距副标题 29px、内边距 25px。
- 目标输入区最小高 105px、内边距 15px、圆角 10px、14px / 1.7；帮助文字距输入区 8px、距下一字段 23px。期限选项内边距 9px 13px、间距 8px，可换行。
- 表单操作区上间距 27px、上内边距 19px并带分隔线；说明最多 340px。取消不会创建目标或写入日历。
- “生成计划草稿”仅生成可编辑草稿。草稿沿用目标详情中的步骤行尺寸，允许编辑目标名、期限、步骤标题、产出和预计时长；保存后才创建目标，随后使用返回的首步候选进入同一排期流程。
- 从助手创建目标也返回并进入此结构化草稿流程，不绕过编辑、保存或排期确认。
- 移动端表单操作区改为纵向，说明在前、按钮在后；取消与生成/保存按钮均占满可用宽度。请求失败保留全部输入和编辑内容。

### 4.5 设置

- 内容最大宽 910px；桌面为 `175px + minmax(480px,1fr)`，列间距 30px。设置导航项内边距 10px 12px，选中底为 `nav-active`。
- 设置区块下间距 25px；标题 14px / 670，说明 11px / 1.6。设置行最小高 64px，内边距 13px 17px，网格 `1fr + auto`、间距 18px；值控件最小宽 140px。
- 开关视觉尺寸 34×20px，实际按钮触控区至少 44×44px，并有明确的开启/关闭文本供辅助技术读取。
- 可用时间卡内边距 17px；每日设置网格为 `70px + 1fr`，间距 12px、上间距 13px。时段 chip 内边距 7px 10px、间距 7px，可换行。
- 可用、保护和偏好时段须分组清晰；偏好只影响排序，不代表可用。空可用时间表示“没有可排期时段”，不能解释成全天可用。保存按钮右对齐、上间距 16px，保存期间禁止重复提交但保留内容。
- 移动端设置改单列；分组导航可横向滚动或换行，设置行改为上下排布，值控件宽 100%。日历导入显示文件选择、大小/格式错误、导入中和真实导入数量；未实现的偏好不得做成可点击假控件。

### 4.6 全局助手

- 桌面抽屉宽 400px、高 100dvh，右对齐，背景 `surface`，左边框分隔。头部内边距 24px 22px 18px，标题 14px / 670；关闭按钮有“关闭助手”可访问名称。
- 消息区为剩余高度并垂直滚动，内边距 23px 20px；用户消息最大宽 82%，内边距 10px 13px，圆角 `14px 14px 4px 14px`；助手消息上间距 22px、12px / 1.7。
- 时间候选为可激活按钮，内边距 13px、圆角 10px、上间距 9px。每项必须显示目标名、步骤名、完整日期时段和理由；不使用 radio，不显示“确认后才写入”或二次确认按钮。
- Composer 外边距 0 18px 20px，内边距 12px 13px，圆角 13px。文本域随内容增高至约 5 行，发送按钮视觉尺寸 25×25px、触控区至少 44×44px。候选生成、已存在或失效时均不禁用 Composer；新消息会使旧候选失效。
- 移动端使用底部 sheet：宽 100%、高度 100dvh，顶部圆角 13px，适配安全区；头部和 Composer 固定，消息区独立滚动。软键盘弹出时输入框和发送按钮保持可见。
- 助手是模态层时锁定背景滚动并隔离背景焦点；宽桌面非模态停靠时不得强制夺走当前焦点。打开后焦点置于标题或输入框，关闭后返回触发按钮。

## 5. 状态、反馈与异常

### 5.1 通用状态

| 状态 | 必需表现 |
|---|---|
| 首次加载 | 按真实布局显示骨架或局部进度，保留标题和导航；不显示示例事件、虚假百分比或假消息。 |
| 局部刷新 | 尽量保留已读内容与滚动位置，只更新对应区域；输入内容不得清空。 |
| 写请求中 | 仅锁定相关操作并显示进行中文字/进度，防止重复提交；Composer 按上述规则继续可用。 |
| 成功 | 更新真实 DTO 后显示简短结果；排期、移动、取消等结果显示明确目标名和步骤/事件名，并提供可用的撤销。 |
| 空态 | 说明“没有什么”以及一个真实可执行的下一步；不用装饰性卡片填满空白。 |
| 局部失败 | 在原区域显示可读原因和“重试”，其他已加载区域继续可用；不得用 Toast 代替必要的表单错误。 |
| 整页失败 | 保留应用导航，显示说明、重试和可返回页面；不能无限骨架或白屏。 |
| 离线/超时 | 明确“尚未确认完成”，保留草稿和输入；重试同一逻辑写操作沿用相同 Idempotency-Key。 |

- 撤销提示使用深色 `toast`，置于底部内容上方并避开移动导航，包含“撤销”按钮；自动消失不能成为唯一撤销入口，提示未读期间由状态消息可读。
- 按钮只有在服务端确认后才呈现完成态。乐观更新只允许用于可立即回滚且不造成误解的界面状态，不得伪造排期、签到、保存或导入成功。
- 所有写请求带唯一逻辑操作键；同次重试复用，用户发起新操作才生成新键。409、422、401 等错误不得静默吞掉。

### 5.2 业务异常

- `401`：说明登录已失效并进入重新登录；保留未提交的文本草稿，不能继续展示可写假象。
- `409` 版本冲突：说明数据已更新，刷新相关详情/候选后再操作；不得静默覆盖。撤销因事件已修改或恢复冲突被拒绝时，说明原因并保留现状。
- `422`：在对应字段旁显示具体校验问题，焦点移到首个错误；日历重叠、时长、感知时区时间格式等均需可读提示。
- 候选过期或被新消息取代：标为不可用并提供“重新找时间”；不能继续提交旧版本。
- 接受候选、开始执行、延长 15 分钟发生冲突或违反可用/保护时段：原安排保持不变，给出原因和重新安排入口。
- 只有一个进行中的执行；重复开始或重复签到时重新读取并展示当前真实状态，不创建第二个会话。
- 草稿生成失败或回退模板时，明确来源和可重试操作；不能声称 AI 已生成实际未生成的内容。

### 5.3 关键空态文案方向

- 今天无下一步：“今天还没有待推进步骤”，提供“查看目标”或“找时间”；今日事件为空时显示独立空态。
- 无目标：“从一个想实现的结果开始”，主操作为“新目标”。
- 无待安排步骤：“所有待办步骤都已有时间”，不显示虚假的拖拽提示。
- 助手无消息：用简短提示说明可安排、调整或创建目标，不预置用户消息和候选。
- 无可用时段：提示先调整可用时间；偏好时段为空不影响可用时段判断。

## 6. 无障碍与输入

- 使用语义化 `nav/main/aside`、连续标题层级、真实链接和按钮；当前导航使用 `aria-current="page"`。不可点击的说明不能用按钮外观。
- 所有表单控件有持久可见标签；占位符不能替代标签。必填、帮助和错误通过可访问描述关联，错误汇总使用警报语义。
- 键盘焦点顺序与视觉顺序一致；焦点样式为至少 2px 的 `blue` 外轮廓并留 2px 间距，不能被卡片 `overflow` 裁切。正文与关键控件对比度至少 4.5:1，大文字和非文本控件至少 3:1。
- 模态对话框和移动 sheet 使用可访问名称、焦点圈定、Escape 关闭及关闭后的焦点恢复；有未保存内容时，Escape 不应无提示丢失内容。
- 状态更新使用 `role="status"` 的礼貌播报，提交错误使用 `role="alert"`； loading 提供可访问名称，避免连续重复播报计时。
- 进度条暴露当前值、最小值 0、最大值 100 和目标名称。开关使用 switch/checked 状态，步骤勾选同步暴露完成状态。
- 日历提供与网格等价的键盘/列表操作路径；拖动、缩放、长按都不是唯一方式。图标按钮均有可访问名称，装饰图标对辅助技术隐藏。
- 支持减少动态效果偏好；骨架、抽屉和 Toast 不依赖大幅动画。页面在 200% 缩放、系统大字体、键盘单独操作下仍可完成核心流程。
- 所有日期选择、时段编辑、候选执行、撤销、签到和导入均可仅用键盘完成；触控目标至少 44×44px，相邻小目标保留足够间隔。
