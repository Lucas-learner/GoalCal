# GoalCal Web 接口契约

当前源码依据：`goalcal/web/http.py` 的 `SPECS`、`schemas.py`、前端 `api/types.ts`。基础路径 `/api/v1`，同源 HttpOnly 会话 Cookie。旧 Action/领域函数说明保存在 [历史契约](archive/接口契约-streamlit-2026-11-17.md)。

## 通用规则

写请求为 JSON，必须携带合法同源 `Origin` 和 `Idempotency-Key`；同一次操作重试复用键，新的操作使用新键。受版本保护的资源带 `version`，冲突返回 409。日期时间传带时区的 ISO 字符串，业务按用户时区计算，库内存 UTC。用户身份来自认证，不接受请求任意指定租户。

未认证 401，非法来源 403，不存在/不可访问 404，输入错误 422；具体错误对象由 `web/http.py` 的 `error` 定义。前端展示本地化错误并保留表单，不能把错误当作成功。

## 接口组

| 路径（省略基础路径） | 方法 | 用途 |
|---|---|---|
| `/me` | GET / PATCH | 当前用户、语言偏好；PATCH 尚不支持时区 |
| `/today` | GET | 今日下一步、执行与恢复信息 |
| `/habits`、`/habits/{id}` | GET / POST / PATCH（按资源） | 习惯列表、创建、规则变更和历史。详情支持 `through` 查询截至指定日期的历史，`date` 查询指定日可记录的当次 |
| `/habits/preview`、`/habits/{id}/status` | POST | 预览生效日、时段冲突与受影响安排，设置进行中、暂停或归档 |
| `/habits/{id}/occurrences` | POST | 本次排期、完成、跳过、取消或撤销完成 |
| `/goal-intake`、`/goal-drafts` | POST | 澄清与计划预览 |
| `/goals`、`/goals/{id}` | GET / POST / PATCH / DELETE（按资源） | 目标查询、创建、更新、删除 |
| `/goals/{id}/refill`、`/steps/{id}` | POST / PATCH | 后续步骤与步骤编辑 |
| `/calendar/events`、`/events/{id}` | GET / POST / PATCH | 事件列表、创建、移动 |
| `/events/{id}/cancel` | POST | 取消事件 |
| `/steps/{id}/proposals`、`/proposals/{id}/accept` | POST | 排期候选与接受 |
| `/steps/{id}/schedule` | POST | 指定时间排期 |
| `/operations/{id}/undo` | POST | 撤销可撤销操作 |
| `/events/{id}/start`、`/steps/{id}/start` | POST | 开始执行 |
| `/execution-sessions/{id}/checkin`、`/events/{id}/checkin` | POST | 完成、部分或调整签到 |
| `/preferences/availability` | GET / PUT | 可用、保护、偏好时段、缓冲与上限 |
| `/assistant`、`/assistant/turns`、`/assistant/clear` | GET / POST | 线程读取、对话、清空。重复行动可返回 `create_habit`，供新建表单预填，保存走习惯创建接口 |
| `/calendar/import` | POST | 手动 `.ics` 文本导入（与自动订阅源相互独立） |
| `/calendar/sync` | GET | 读取只读导出订阅配置（`feed`）与外部日历订阅源列表（`sources`） |
| `/calendar/sync/feed`、`/calendar/sync/feed/rotate` | PUT / POST | 启停及筛选导出内容（目标块/习惯/手动日程）、重置私密订阅 Token |
| `/calendar/sync/sources`、`/calendar/sync/sources/{id}` | POST / PATCH / DELETE | 添加并首次校验同步外部日历 URL、修改名称/链接/频率/启停、删除源并清理对应同步日程 |
| `/calendar/sync/sources/{id}/sync` | POST | 手动触发单个外部日历源立即同步（支持失败状态落库与错误展示） |
| `/metrics`、`/feedback` | GET / POST | 指标读取、反馈提交 |

公开只读日历订阅出口位于 `GET / HEAD /calendar/feed/{token}.ics`（位于网关层，不要求浏览器会话 Cookie，凭高熵私密 Token 鉴权，支持 `If-None-Match` → `304`，响应 `Cache-Control: private, no-cache`）。

认证页面位于 `/_goalcal/login`、`/_goalcal/register`，退出为 `POST /_goalcal/logout`。登录表单额外使用 CSRF 表单令牌。`/_goalcal/health` 检查 Web 就绪状态，成功 200，未就绪 503。

契约修改需同步前端类型、客户端及 API/业务/E2E 测试；不要直接暴露旧 `Conversation.state_json` 为 API 返回值。

## 实现边界

- `frontend/src/api/types.ts` 定义客户端 DTO，`goalcal/web/schemas.py` 校验请求；字段与允许值以这两处和 `SPECS` 为准，归档迭代契约不再作为实现依据。
- `web/http.py` 管理认证、来源检查、事务和幂等；`web/core.py` 与助手在用户边界内执行业务。服务方法不自行提交事务，模型调用与外部日历 HTTP 拉取不得持有 SQLite 写锁。
- `llm/` 输出结构化理解或规划结果，不直接写库；`domain/` 承担可独立测试的规则与决策。前端只渲染并发起操作，不绕过 API 写入。
- 排期接受时重新验证冲突、期限、偏好和版本；撤销也要检查后续修改及恢复冲突。不能以先前候选仍可见作为当前可执行的依据。
- `GET /today` 与 `GET /calendar/events` 返回习惯当次和周进度。习惯时间块的 `kind` 为 `habit`，用关联的当次版本通过 `/habits/{id}/occurrences` 修改。新增周次数安排可携带 `habit_version`，修改已有当次使用 `version`。账号对每个习惯的同一天最多记录一次。带时段的固定习惯首次访问时按需补齐四周占用，日历导入会跳过与已确认习惯时段冲突的条目。
