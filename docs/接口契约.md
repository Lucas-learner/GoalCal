# 接口契约（改动需全员同步）

> 目的：7 个人并行开发时，**只有这三个接口不能随便改**。冻结日期：2026-10-22。

## 1. 理解层 → 执行层

```python
def parse(text: str, now: datetime, use_llm: bool | None = None) -> tuple[Action, str]
```

`Action`（`goalcal/llm/action.py`）是唯一允许跨层传递的结构：

```json
{
  "intent": "add_event | move_event | delete_event | query_events | create_goal | log_progress | set_state | chat",
  "title": "meeting",
  "start": "2026-10-22T10:00:00+08:00",
  "end": "2026-10-22T11:00:00+08:00",
  "duration_min": 60,
  "target": "workout",
  "deadline": "2026-11-20",
  "state": "tired | busy | uninspired | fresh",
  "progress_target": "script",
  "confidence": 0.9,
  "raw": "原始输入"
}
```

规则：

- 第二返回值是 parser 标识（`llm:parse-v1` / `rules:v1`），必须写日志，用于评测归因。
- `start` 带时区偏移；`end` 由 `Action.normalized(now)` 补齐。
- 任何解析失败 → 抛给 `parse()` 兜底，**不允许把异常抛到 UI**。

## 2. 排期引擎

```python
def propose(
    req: Requirement,          # est_min, energy(0/1/2), kind, min_chunk
    now: datetime,             # 本地 aware
    busy: list[BusyBlock],     # 本地 aware
    prefs: Preferences | None,
    days: int = 5,
    top_n: int = 3,
    deadline: date | None = None,
) -> list[Candidate]           # 已按分数降序
```

约定：

- 纯函数，**不许查库**。数据由调用方（`agent.py`）查好传进来。
- 返回的候选之间至少相隔 1 小时，避免三个按钮指向同一个空档。
- 每个候选必须至少有一条 `reasons`，UI 直接展示。
- 新增打分维度只能追加权重常量，不能改函数签名。

## 3. 执行层

```python
def handle(session, user_id, text, now, tz) -> Reply
def accept(session, user_id, step_id, candidate, tz) -> str
```

- `handle` 是**唯一**允许写事件的入口（除 seed 外）。
- 所有写操作在调用方的 `session_scope()` 里提交，函数内只 `flush`。
- 失败要返回人话，不抛裸异常。

---

## 4. 数据约定

| 规则 | 说明 |
|---|---|
| 时间存储 | DB 一律 **UTC naive**；进出用 `timeutil` |
| 计算 | 一律本地 aware（`Asia/Shanghai`） |
| 事件类型 | `external` 用户日程 / `block` 目标执行块 / `buffer` |
| 步骤状态 | `todo → scheduled → done`（`skipped` 为放弃） |
| 进度 | 按 `est_min` 加权，不用“完成个数 / 总数” |
| 删除 | 事件硬删；目标用 `status=archived` 软删 |

## 5. 分支与提交

- `main` 保持可运行，任何人合并前必须 `pytest -q` 全绿。
- 分支：`feat/<模块>-<一句话>`，例 `feat/scheduler-energy-curve`。
- 提交信息：`<模块>: <做了什么>`，例 `scheduler: 加入午饭保护`。
- 只有集成 owner 合并 PR；冲突由模块 owner 解决。
