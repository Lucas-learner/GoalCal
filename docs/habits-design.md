# GoalCal 习惯功能设计

Web 首版 · 已实现于仓库

习惯有自己的重复规则和完成记录，可以独立创建，也可以关联一个目标。Today 和 Calendar 操作的是具体的一次习惯。排好的习惯与目标步骤共用时间线，待排的习惯与目标步骤共用安排时间的入口。

## 创建与管理

「目标」和「习惯」各有一级入口。桌面侧栏将「习惯」放在「目标」和「日历」之间。移动端底栏依次显示「今天、目标、习惯、日历、设置」，五项等宽，沿用图标、文字标签和至少 44 px 的触控高度。用户可以从主导航直接找到目标进度或习惯规则。

「目标」和「习惯」采用相同的管理布局。桌面左侧为目录、右侧为详情，移动端先看目录，点选后进入详情。习惯按进行中、已暂停和已归档展示，详情沿用进度条和下一步卡片的布局，可安排和完成下一次，以及查看记录、补记、暂停、恢复和归档。从习惯页新建时进入独立表单，预览后保存。从 Calendar 时间格新建时在日历弹窗中填写同一套表单，预填开始日期、时间和时长。

| 重复规则 | 设置 | 创建后 |
| --- | --- | --- |
| 每天或每周指定日 | 选择每天或每周的星期几，可加默认开始时间 | 到指定日期出现一次。设了时间的进入时间轴，只有日期的进入待安排 |
| 每周完成 N 次 | 每周 1–7 次，具体日期由用户选择 | 显示「本周 0/3 次」。可直接完成今天这一次，也可先安排日期和时间 |

两种规则都填写名称、开始日期和预计时长，默认从今天开始、预计 30 分钟，可选关联一个进行中的目标。保存前预览最近几次的日期和冲突，周次数规则预览起始周与目标次数。当天的默认时间已经过去时，第一次显示为「待安排」。关联的目标会出现在习惯详情中，习惯完成独立计数。目标暂停、完成或归档时，习惯按自己的规则继续，已关联的历史仍可查看。

从习惯页新建时，先填写名称和重复频率，再预览安排。开始日期、时长、默认时间和关联目标收在「时间与关联目标」。也可从「问 GoalCal」描述想重复做的事，例如「我想每周跑三次步」，打开助手预填的草稿后再确认保存。

详情优先展示当周。固定习惯可以从星期格查看和处理对应日期，弹性习惯显示已完成次数、剩余次数和选定的日期。当天可直接完成，翻看历史记录时，本周节奏仍留在上方。补记和历史在同一个折叠区。

## Today 与 Calendar

| 当次状态 | Today | Calendar |
| --- | --- | --- |
| 今天有时段 | 与目标步骤一起按时间排序，行内可完成，点击标题查看本次 | 使用同规格时间块，加重复图标和可读标签。可点开完成、改时间或跳过 |
| 今天有日期，时间待定 | 显示在「今日安排」内的「待安排」区，可直接完成或安排时间 | 与未排期的目标步骤共用「尚未安排」，习惯行显示所属日期 |
| 每周次数尚未达成，今天未选定一次 | 在「今日安排」底部显示一条可选行动，如「运动 · 本周 1/3 次」 | 「尚未安排」显示所看周的进度和「安排一次」，选日后显示在当天 |

Today 的「正在执行」继续显示当前执行中的目标步骤。没有进行中的执行时，「接下来」从今天时段尚未结束的可执行事项中按开始时间选一条，习惯和目标步骤按相同顺序比较。在没有这类事项时，今天待安排的习惯、无日期的目标建议和已有的未来目标安排依次补位。按周次数的可选行动留在下方。达标后自动收起，已经排好的块照常显示。Today 根据两类行动一起判断是否显示空态。若安排的时段已经过去但仍是当天，用户仍可从「今日安排」完成本次。

Calendar 沿用桌面周视图、移动端单日视图和现有待安排面板。桌面可将待安排项拖入时间格，移动端和键盘用户可通过「安排时间」选日选时。周视图按可见范围列出待安排的习惯，日视图只列当天的待排项，并显示该日所属周的次数进度。「安排一次」可以只选日期，选定时间后才占用时段。已处理的记录带状态展示，没排过时间的记录可从待安排面板的「习惯记录」展开查看。

## 完成本次与调整安排

Today 和 Calendar 打开同一个本次详情，显示名称、日期、时段或预计时长，以及对应的完成和排程操作。「查看习惯」进入管理页，修改重复规则有独立入口。完成或跳过后沿用现有的撤销提示。

| 操作 | 用户看到的结果 |
| --- | --- |
| 完成本次 | 当天可直接勾选，Today、Calendar 和习惯记录同步。已安排的时间保留展示，提前完成时释放尚未开始的占用。预计时长用于排期，勾选即计一次。未来日期到当天才可完成 |
| 跳过本次 | 从待做列表移走，释放时段，习惯记录显示「已跳过」，后续按规则出现 |
| 改时间 | 固定日习惯可在原日期内改时段，按周次数的习惯可在同周改日期或时段。拖动和详情编辑只修改本次。失败时保留原安排 |
| 移除时间 | 本次回到所属日的「待安排」。按周次数的习惯另外提供「取消这次安排」，取消后可以在该周另选日期 |
| 补记或撤销 | 习惯详情可按实际发生日期补记，固定日限规则生效且应做的日期，按周次数限规则有效的日期。已完成项可撤销，进度随之重算。过去日期撤销回原状态；若这是临时补记而此前没有安排，则移除该条记录 |

每天每个习惯最多记一次。周次数规则以习惯时区的周一至周日为周期，达标后仍可从习惯详情主动安排或记录额外次数。若同一周已有未来安排，今天提前做可以直接记录，未来安排保留，用户可单独取消。跨过本地午夜后，未处理的固定日项和已经选日的周次数项显示为「未完成」，留在历史和对应日期。周次数习惯在从未选日的日期没有待完成项。任何未完成次数都不会带入下一天的待办、目标恢复列表或下周配额。

## 规则变更、暂停与冲突

在习惯详情中就地修改规则，保存前显示生效日期。固定日规则从次日起生效，涉及周次数的规则变更从下周一生效。换规则时保留已经完成或跳过的记录，释放受影响的未来占用，并明确提示会替换哪些已调整的未来安排。

暂停或归档立即移除当天与未来尚未处理的安排，释放时段，保留历史和已处理的记录。恢复从当天开始，当天已经完成或跳过的记录继续有效。若恢复时默认时间已过，当天显示为待安排。暂停期间无应做次数。周次数目标在生效不足整周时仍显示实际次数与原目标，历史标记为「部分有效周」。

有时段的习惯与已有排期共用冲突校验，使用账号的可用时段、保护时段和缓冲。习惯占用会扣除可用时间，现有「每日目标时间上限」仍按目标步骤计算。已保存的占用优先。默认时段冲突时，这一次保留在原日期，显示「时间冲突」并提供「另选时间」。并发修改同一时段时，以实际保存结果为准，失败方保留输入并看到最新状态。首版滚动确认从今天起四周的默认时间，范围以外可以预览重复日期，标记为待确认。后续生成时若已有其他事件占用，按同一冲突规则处理。习惯使用创建时的账号时区，时段以 UTC 保存，换设备时保持同一日期归属和统计周期。

## 首版实现边界

后端分别保存带生效日期的习惯规则和当次记录。每次有稳定标识，按「习惯 + 日期」约束同日唯一。带时间的记录关联日历占用。完成状态由当次记录提供，Today、Calendar 和习惯详情读取同一结果。固定日的历史以当时生效的规则和暂停记录为准，即使用户当天没有打开应用。改期、完成、跳过和释放时段在对应写入中一起处理，按现有版本、幂等和撤销规则校验。目标步骤的完成和计划补充仍由目标流程触发。

首版包含手动排程、完成、跳过、补记以及按日记录和周次数统计。后续可以在这套记录上增加连续达成统计、助手排期、计时和提醒。普通重复日程继续作为独立的日历功能设计。

## 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 在 320 px 宽的移动端从「目标」切到「习惯」 | 点击底栏一次即可打开习惯管理页，当前项高亮。五项中英文标签均可读，底栏避开系统手势区域 |
| 创建「每天阅读 30 分钟」，时间留空 | 今天在 Today 和 Calendar 待安排中只出现一次。安排时段后从待安排移到时间线，完成后两页同步，明天照常出现 |
| 每周二、四 19:00 跑步，周四已有会议 | 周二有时间块，周四显示待另选时间。周四改到 20:00 或跳过，下周仍按原规则出现 |
| 每周运动三次，先安排周五，周三提前记录 | 今日立即计一次，周五安排保留。周内完成第三次后收起 Today 的进度提醒，下周重新计数 |
| 周五的灵活习惯拖到周六 | 完成后仍计入原周。拖到下周或已有同习惯记录的当天时显示错误，原安排保留 |
| 一次固定日习惯没做，隔天打开 Today | 昨天记录显示「未完成」，今天只有今天这一次。补记昨天后，昨天的状态和对应进度一起更新 |
| 周三把每周三次改为两次 | 本周仍按三次计数，下周按两次。已完成记录保留，保存前提示下周哪些安排会被替换 |
| 同时在两个页面完成同一次或争用同一时段 | 完成最多计一次。相互冲突的占用最多提交一条，失败页面刷新并保留输入 |
