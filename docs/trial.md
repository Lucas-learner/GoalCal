# 邀请试用与反馈迭代

当前可以先邀请少量用户试用，观察真实网络、使用流程和 ngrok 免费额度。尚未以 5–20 人长期连续使用证明稳定性。

访问入口：https://disciplelike-preoccupiedly-kay.ngrok-free.dev

首次打开可能出现 ngrok 提示，点击 **Visit Site**，然后选择 **邀请码注册**。用户名为 3–32 个英文字母、数字或下划线，密码至少 12 个字符。每个邀请码只能注册一个账号，默认 7 天内有效。请把不同邀请码分别给不同试用者；不要分享 owner 账号和密码。

## 自动记录的内容

- 注册、登录成功/失败、退出和管理操作。
- 操作类型、内部账号 ID、时间、耗时、操作编号；错误类型及对应代码位置。
- AI 外部请求成功/失败和耗时，额度或写事务导致的降级原因。
- 原有功能埋点：解析意图和解析器、排期建议/接受、完成、签到恢复等。
- 应用和隧道运行日志、异常退出与自动重连信息。

诊断日志保存在生产数据库旁的 `var/logs/` 并按大小轮转；不自动记录密码、邀请码、密钥、订阅链接、完整聊天或日历正文。诊断数据不发送到额外的统计平台。本机业务数据库仍按产品功能保存目标、事件和签到等记录。

## 用户反馈

登录后打开侧栏 **反馈问题 / 建议**，填写类型、复现步骤、预期和实际结果。系统错误会显示问题编号，之后的反馈会自动附上该编号。

反馈文本由用户主动提交，作为 `user_feedback` 记录保存在本机业务数据库，随每日备份保存；不把反馈正文复制到运行日志。用户只能通过自己的认证会话提交和访问自己的记录，本机维护者可通过管理命令查看并处理反馈。不要在反馈中填写密码、密钥或其他人的隐私。

网络断开或页面打不开时，用户可直接把发生时间、手机网络、页面表现发给主机所有者。客户端尚未连接到服务器的问题，不会全部出现在应用日志中。

## 本机维护命令

```sh
export GOALCAL_ENV_FILE="$PWD/.env.production"
.venv/bin/python -m goalcal.admin invite
.venv/bin/python -m goalcal.admin diagnostics --days 7
.venv/bin/python -m goalcal.admin feedback
.venv/bin/python -m goalcal.admin feedback --id 123
.venv/bin/python -m goalcal.admin feedback --resolve 123
```

`diagnostics` 汇总功能次数、解析意图、操作耗时与失败、AI 调用结果及反馈编号，不导出反馈正文。默认 `feedback` 列表同样不显示正文，`--id` 才查看单条详细反馈。历史纯文本日志不会被诊断汇总误当成结构化记录。

## 迭代方式

收集日志和反馈 → 按影响范围/频率筛选问题 → 结合时间与问题编号复现 → 修复并测试 → 备份后更新 → 回看是否改善 → 将反馈标记为已处理。

这套系统自动收集诊断信息和主动反馈，不会根据一条反馈自行修改或发布代码，也没有设置无人值守的每日 AI 审查。之后让开发助手执行诊断汇总并查看指定反馈，即可基于真实记录继续迭代。
